### 原因2：内容解析器硬编码限制

**问题**：`content_parser.py`中硬编码了最大项目数限制。

**代码位置**：
- 第140行：`steps = steps[:4]`  # 流程图最多4个步骤
- 第185行：`items = items[:4]`  # 时间线最多4项

**后果**：
- 即使AI提取了5个假设，解析器也只取前4个
- **违反配置化原则**（硬编码参数）

### 修复3：配置化内容解析器限制（辅助修复）

**文件**：`extract_web/converter/services/content_parser.py`

**修改内容**：将硬编码的4改为从配置读取（虽然这里已经正确解析，但仍需配置化）

```python
# ❌ 修改前（硬编码）
steps = steps[:4]
items = items[:4]

# ✅ 修改后（从配置读取）
max_steps = config.get("ppt_generation.layout_types.flow_diagram.max_steps", 6)
if len(steps) > max_steps:
    logger.warning(f"流程图步骤数({len(steps)})超过最大限制({max_steps})，将截断")
    steps = steps[:max_steps]

max_items = config.get("ppt_generation.layout_types.timeline.max_items", 6)
if len(items) > max_items:
    logger.warning(f"时间线项目数({len(items)})超过最大限制({max_items})，将截断")
    items = items[:max_items]
```

**文件**：`config/application.yaml`

**添加配置项**（已在第一次修复时添加）：
```yaml
ppt_generation:
  layout_types:
    flow_diagram:
      enabled: true
      arrow_style: true
      max_steps: 6                   # 最多显示步骤数
    timeline:
      enabled: true
      vertical: true
      max_items: 6                   # 最多显示项目数
```

**效果**：
- ✅ 默认值从4提升到6
- ✅ 可通过配置灵活调整
- ✅ 遵循配置化原则
- ✅ 添加警告日志便于调试

## 技术要点

### 1. AI Prompt优化原则

**核心**：通过**具体示例**教AI正确的提取格式

**关键点**：
- ✅ 用**标题**分隔不同的列表
- ✅ 用**缩进**表示层次结构
- ✅ 提供**正确示例**和**错误示例**对比
- ✅ 强调"多个并列列表必须分开"

### 2. 配置化原则

**核心**：绝对禁止hardcode任何配置参数

**违反示例**：
```python
# ❌ 错误
steps = steps[:4]
max_items = 4
```

**正确示例**：
```python
# ✅ 正确
max_steps = config.get("ppt_generation.layout_types.flow_diagram.max_steps", 6)
max_items = config.get("ppt_generation.layout_types.timeline.max_items", 6)
```

### 3. 缓存管理

**问题**：缓存文件保存了旧的提取结果

**解决**：
- 修改prompt后需要清空缓存
- 或者实现缓存版本控制机制
