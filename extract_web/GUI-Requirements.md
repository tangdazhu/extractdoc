## 四、核心转换流程

### 4.1 图片转文件 (Word/PDF) - ImgToFile ✅ (已完成实现)

#### 4.1.1 用户界面交互 ✅ (已完成实现)

1.  用户在"图片转文件"主标签页下，选择"图片转Word"或"图片转PDF"子标签页，以确定最终输出格式。
2.  用户通过文件上传区域添加一个或多个图片文件。
    -   前端限制：最多选择10个文件，单个文件大小不超过500MB。相关提示显示在"+ 添加文件"按钮下方。
    -   已选文件列表会显示在上传区域下方，可移除单个文件。
3.  用户可勾选或取消"合并为一个文件"复选框（默认选中）。
4.  点击"开始转换"按钮：
    -   按钮文字变为"等待转换中..."，背景色变为黄色，主、子标签页不可切换。
    -   向后端发起处理请求，包含图片文件、合并选项 (`merge_output`) 和输出格式 (`output_format`：`docx` 或 `pdf`)。
5.  转换完成后：
    -   "等待转换中..."按钮恢复为"开始转换"，主、子标签页恢复可切换。
    -   下方的"转换结果"表格更新，显示本次转换的结果。

#### 4.1.2 后端处理逻辑 ✅ (已完成实现)

1.  接收前端传来的图片文件、`merge_output` 和 `output_format` 参数，生成`request_id`，记录`start_time`。
2.  为当前用户和当前日期（`YYYYMMDD`）创建或确认目标存储路径（`uploads` 和 `converted_files`）。
3.  保存上传的图片到 `uploads` 目录。
4.  **核心处理（两阶段）**：
    -   **阶段一 (OCR到DOCX)**：对于每个上传的图片，调用 `pic_file_converter.process_images_to_files`，该函数内部调用外部Python脚本 (`extract_text_from_images.py`)，指示其输出一个临时的 `.docx` 文件（文件名包含 `_tempScriptOutput_<request_id>.docx`）到用户的当日 `converted_files` 目录中。
    -   **阶段二 (视图内合并/转换)**：
        -   **若 `merge_output` 为真**：
            -   使用 `python-docx` 库将阶段一生成的所有临时 `.docx` 文件合并为一个主 `.docx` 文件（文件名包含 `_intermediate_<request_id>.docx`）。
            -   **如果目标 `output_format` 是 `pdf`**：调用 `word_to_pdf_converter.convert_word_to_pdf` (其内部使用LibreOffice) 将合并后的主 `.docx` 文件转换为 `.pdf` 文件。成功则删除主 `.docx`；失败则保留主 `.docx`，并向用户发送提示。
            -   删除阶段一生成的各个临时 `.docx` 文件及中间合并的 `.docx` (如果已转PDF)。
            -   为最终的合并文件（`.docx` 或 `.pdf`）创建一个 `.meta` 文件，存储所有原始上传文件的名称列表（逗号分隔）。
        -   **若 `merge_output` 为假**：
            -   遍历阶段一生成的每个临时 `.docx` 文件：
                -   **如果目标 `output_format` 是 `pdf`**：调用 `word_to_pdf_converter.convert_word_to_pdf` 将其转换为 `.pdf`。成功则删除临时 `.docx`；失败则保留临时 `.docx`。
                -   **如果目标 `output_format` 是 `docx`**：将临时 `.docx` 文件移动/重命名为最终文件名。
                -   为每个最终生成的单文件（`.docx` 或 `.pdf`）创建一个 `.meta` 文件，存储其对应的原始上传文件名。
5.  计算`duration_seconds`。返回包含所有已处理文件信息（原始文件名、转换后文件名、下载URL、状态、`duration_seconds`）的JSON响应给前端。清理所有带`request_id`的临时文件。

#### 4.1.3 外部脚本 ✅ (已完成实现)

-   接受输入图片路径、输出文件路径和 `--format docx` 参数。
-   使用 PaddleOCR 等库提取图片中的文本和表格。
-   将提取内容保存到指定输出路径的 `.docx` 文件。

### 4.2 文件转PDF (Word/Excel/PPT/TXT to PDF) - FileToPdf ✅ (已完成实现)

#### 4.2.1 用户界面交互 ✅ (已完成实现)
(与图片转文件类似，用户选择对应子标签页如"Word转PDF"，上传相应文件类型)

#### 4.2.2 后端处理逻辑 ✅ (已完成实现)
1. 接收前端文件、`merge_output` (`true`时合并为单一PDF) 和 `sub_tab` (如 `wordToPdf`)，记录`start_time`。
2. 文件被复制到 `converted_files` 目录，命名含 `_prePdf_<request_id>.<ext>`。
3. **若 `merge_output` 为真**:
    - 对每个上传文件（如 `.docx`），调用相应的转换器 (如 `word_to_pdf_converter.convert_word_to_pdf`) 生成临时的单个PDF文件（文件名含 `_merged_temp_<request_id>.pdf`）。
    - 使用 `PyPDF2` 将所有临时PDF文件合并为一个最终PDF。
    - 清理所有原始上传文件的副本和临时PDF。
    - 创建 `.meta` 文件。
4. **若 `merge_output` 为假**:
    - 对每个上传文件，调用相应的转换器 (如 `word_to_pdf_converter.convert_word_to_pdf` for DOCX, `excel_pdf_converter.convert_excel_to_pdf` for XLSX, `ppt_pdf_converter.convert_pptx_to_pdf` for PPTX, `txt_to_pdf_converter.convert_txt_to_pdf` for TXT) 直接生成最终PDF。
    - 清理原始上传文件的副本。
    - 创建 `.meta` 文件。
5. 计算`duration_seconds`。返回JSON结果（包含`duration_seconds`）。所有转换器（Word, Excel, PPT）优先使用基于LibreOffice的通用转换逻辑。

   - **PDF转PPT**: 可选择转换方法
     - "使用截图方式" - 将PDF页面转为图片插入PPT
     - "使用Office转换方式" - 使用LibreOffice转换
   - **PDF转TXT**: 默认使用PyMuPDF方法 (快速文本提取)
3. 支持批量上传和合并选项 (Word/TXT支持合并，Excel/PPT暂不支持)

#### 4.3.2 后端处理逻辑 ✅ (已完成实现)
1. 接收前端PDF文件、`merge_output`、`sub_tab` (如 `pdfToWord`) 和 **转换方法选择** (`conversion_method`)，记录`start_time`。
2. PDF文件被复制到 `converted_files` 目录，命名含 `_preFinal_<request_id>.pdf`。
3. **智能转换器选择** ✅ (已完成实现)：
   - **PDF转Word**: 根据用户选择调用不同转换器
     - `pdf2docx` 方法：使用 `pdf_to_word_converter.convert_pdf_to_word` (默认)
     - `libreoffice` 方法：使用 `libreoffice_converter.convert_pdf_to_word`
   - **PDF转Excel**: 使用 `pdf_to_excel_converter.convert_pdf_to_excel` (pdfplumber方法)
   - **PDF转PPT**: 根据用户选择调用不同转换器
     - `screenshot` 方法：使用 `pdf_to_ppt_converter.convert_pdf_to_ppt` (截图方式)
     - `libreoffice` 方法：使用 `libreoffice_converter.convert_pdf_to_ppt`
   - **PDF转TXT**: 使用 `pdf_to_txt_converter.convert_pdf_to_txt` (PyMuPDF方法)
4. **若 `merge_output` 为真**:
    -   **对于 `pdfToWord` (输出DOCX) 和 `pdfToTxt` (输出TXT)**：
        -   对每个上传的PDF，调用选定的转换器生成临时的单个目标文件 (如 `.docx` 或 `.txt`，文件名含 `_indv_conv_<request_id>`)。
        -   DOCX文件使用 `python-docx` 合并；TXT文件直接拼接内容合并。
        -   清理原始PDF副本和临时转换文件。
        -   创建 `.meta` 文件，包含转换方法信息。
    -   **对于 `pdfToExcel` (XLSX) 和 `pdfToPpt` (PPTX)**：合并输出目前不支持。如果勾选合并，会提示用户不支持，并建议单独转换。
5. **若 `merge_output` 为假 (或 `pdfToExcel`/`pdfToPpt` 即使勾选了合并也会按此执行)**:
    - 对每个上传的PDF文件，调用选定的转换器生成最终的目标格式文件。
    - 清理原始PDF副本。
    - 创建 `.meta` 文件，包含转换方法信息。
6. **错误处理和降级** ✅ (已完成实现)：
    - 如果LibreOffice方法失败，自动降级到默认方法
    - 提供详细的错误信息和建议
7. 计算`duration_seconds`。返回JSON结果（包含`duration_seconds`和转换方法信息）。

### 4.4 视频处理 (视频帧提取) - VideoProcessing ✅ (已完成实现)

#### 4.4.1 用户界面交互 ✅ (已完成实现)
1.  用户在"视频处理"主标签页下，选择"视频帧提取"子标签页。
2.  用户通过文件上传区域添加一个视频文件 (如 .mp4, .avi, .mov)。
    -   前端应进行基本的文件类型校验。
    -   显示已选视频文件名。
3.  用户可配置参数：
    -   **场景检测阈值**: 控制场景切换检测的灵敏度（较低值检测更多场景）
    -   **去重分组大小**: 控制相似帧的合并程度（较大值合并更多相似帧）
4.  点击"开始处理"按钮：
    -   按钮文字变为"处理中..."，背景色变为黄色，主、子标签页不可切换。
    -   向后端发起处理请求，包含视频文件和配置参数。
    -   前端实时流式显示后端返回的日志/进度信息。
5.  处理完成后：
    -   按钮恢复为"开始处理"，主、子标签页恢复可切换。

#### 4.4.2 后端处理逻辑 ✅ (已完成实现)
1.  接收前端传来的视频文件和处理参数 (`scene_detection_threshold`, `deduplication_group_size`等)，生成`request_id`，记录`start_time`。
2.  为当前用户和当前日期创建或确认目标存储路径 (`uploads` 和 `converted_files/video_extractions/<request_id>/`)。
3.  保存上传的视频到 `uploads` 目录。
4.  调用 `extract_video_snapshots.py` 脚本执行视频帧提取：
    -   传递输入视频路径、输出目录、场景检测阈值、去重分组大小等参数。

    -   脚本通过 `stdout` 流式输出处理进度和日志信息。

6.  脚本执行完毕后：

    -   记录最终生成的文件名和路径。

8.  在流式响应的最后，发送一个包含最终结果（如提取帧数、下载链接、`duration_seconds`）的JSON对象。
9.  清理临时视频文件和未打包的帧图片。

### 4.5 文字转语音 (Text-to-Speech) - TTS ✅ (已完成实现)

#### 4.5.1 用户界面交互 ✅ (已完成实现)
1.  用户在"语音转换"主标签页下，选择"文字转语音"子标签页。

    -   **文件上传**: 上传包含文字的文档文件 (支持 .txt, .pdf, .docx 等格式)
3.  **字数统计与限制** ✅ (已完成实现)：
    -   实时显示当前字数统计
    -   文本输入：实时计算输入文字数量
    -   文件上传：根据文件大小估算字数（txt: 1字节≈1字符，pdf: 2字节≈1字符，docx: 3字节≈1字符）
    -   当字数超过5000时：
        - 显示红色警告文字："超过5000字限制"
        - 字数统计文字变为红色
        - "开始转换"按钮自动禁用并置灰
        - 鼠标悬停显示"不可点击"样式
4.  用户选择音色模型：
    -   支持多种中文音色：晓晓(默认)、云希、云扬、晓辰、晓涵、晓墨等
    -   每个音色都有详细的描述说明

    -   按钮文字变为"等待转换中..."，背景色变为黄色
    -   向后端发起TTS处理请求
6.  转换完成后：
    -   按钮恢复为"开始转换"
    -   下方显示转换结果，包含音频文件下载链接和处理时长

#### 4.5.2 后端处理逻辑 ✅ (已完成实现)
1.  接收前端传来的文本内容或文件、音色模型选择，生成`request_id`，记录`start_time`。
2.  **文本提取和预处理**：
    -   如果是文本输入：直接使用输入的文本
    -   如果是文件上传：根据文件类型提取文本内容
        - .txt文件：直接读取文本内容
        - .pdf文件：使用PDF解析库提取文本
        - .docx文件：使用python-docx提取文本内容
3.  **文本分段处理**：
    -   将长文本按照合适的长度分割成多个片段（避免单次合成过长）
    -   每个片段单独进行语音合成
4.  **语音合成**：
    -   调用 `text_to_voice.py` 脚本进行语音合成
    -   使用 edge-tts 库和用户选择的音色模型
    -   为每个文本片段生成对应的音频文件
5.  **音频合并**：
    -   将多个音频片段合并为一个完整的音频文件
    -   保存为 .wav 格式
6.  **结果处理**：
    -   为最终音频文件创建 `.meta` 元数据文件
    -   计算`duration_seconds`
    -   返回包含音频文件下载链接和处理信息的JSON响应
7.  **清理临时文件**：清理处理过程中生成的临时文本和音频文件

## 六、技术实现细节

### 6.1 转换方法对比

| 转换类型 | 主要方法 | 备用方法 | 优势 | 适用场景 |
|---------|---------|---------|------|---------|
| PDF→Word | pdf2docx | LibreOffice | 格式保持好，速度快 | 一般文档转换 |
| PDF→Excel | pdfplumber | ~~LibreOffice~~ | 表格提取专业 | 数据表格提取 |
| PDF→PPT | 截图方式 | LibreOffice | 布局保持好 | 演示文稿转换 |
| PDF→TXT | PyMuPDF | ~~LibreOffice~~ | 速度快，准确度高 | 纯文本提取 |
| 文字→语音 | edge-tts | - | 音质高，中文支持好 | 语音合成 |

### 6.2 文件处理流程

1. **上传阶段**: 文件验证 → 临时存储 → 格式检查
2. **转换阶段**: 方法选择 → 转换执行 → 结果验证
3. **后处理**: 文件合并 → 元数据生成 → 临时文件清理
4. **输出阶段**: 结果返回 → 下载链接生成 → 历史记录保存

### 6.3 错误处理机制

- **预检查**: 文件格式、大小、权限验证
- **转换监控**: 实时监控转换进程状态
- **自动降级**: 主要方法失败时自动尝试备用方法
- **详细日志**: 记录完整的错误信息和调试数据
- **用户反馈**: 提供清晰的错误提示和解决建议

### 6.4 TTS专用功能

- **字数限制机制**: 前端实时统计，后端验证，超限自动禁用
- **多音色支持**: 集成多种中文音色，提供详细描述
- **智能分段**: 长文本自动分割，避免单次合成过长
- **文件字数估算**: 根据文件类型和大小智能估算字数
- **音频合并**: 多段音频无缝合并为完整文件
